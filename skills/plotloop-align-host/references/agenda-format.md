# agenda.json 格式

一份 agenda.json = 一场会。它是视频、播放器、会后提示词的唯一数据源；下一版增量也以它为基线做 diff。

## 顶层

```jsonc
{
  "schema": "align-host.agenda.v1",
  "meeting": { ... },        // 会议信息与规则
  "sections": [ ... ],       // 分节，按顺序
  "items": [ ... ],          // 分歧条目，每条一个暂停点
  "challenges": [ ... ],     // 可选：挑战题，挂到某条目上深问
  "delta": { ... }           // 可选：相对上一版的变化，有则开头加"本轮变化"屏
}
```

## meeting

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✓ | 会议名，片头大标题 |
| `subtitle` |  | 片头副标题，默认"AI 写代码之前，先把人对齐" |
| `version` |  | 清单版本，如 `v0.2` |
| `minutes` | ✓ | 建议会长（分钟）。校验器会和各节合计比对 |
| `rules` | ✓ | 开场规则，字符串数组。至少写清"哪些已定不再投票" |
| `phrase.decided` |  | 已定口令模板，默认 `「{id}，决定：……；理由：……；负责人：……；下一步证据：……」` |
| `phrase.pending` |  | 未定口令模板，默认 `「{id}，暂缓；在等：……」` |
| `roles` |  | 参会角色，如 `["产品","设计","客户端","服务端","测试"]` |
| `glossary` |  | 转写热词：编号、专名。会后提示词里会用到 |

## sections[]

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✓ | `S1`… |
| `label` | ✓ | 进度条上的短标签（≤ 8 字） |
| `title` | ✓ | 节标题屏上的全称 |
| `minutes` | ✓ | 本节建议分钟数 |

## items[]

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✓ | 口令编号，如 `A07`。全局唯一 |
| `section` | ✓ | 所属节 `id` |
| `title` | ✓ | 一屏标题，≤ 12 字 |
| `req` | ✓ | 需求原文怎么说 |
| `dev` | ✓ | 研发怎么理解 |
| `risk` | ✓ | 不对齐的风险 |
| `fix` | ✓ | 建议最小修法——**屏幕固定标"建议，非共识"** |
| `decide` | ✓ | 本次要定什么，一个能回答的问题 |
| `minutes` |  | 建议讨论分钟数，默认按节均分 |
| `nature` |  | 分歧类型标签：`明确偏差` / `已定被重新待定` / `资料不可达` / `书面一致待实物验证`… |
| `roles` |  | 需要到场表态的角色 |
| `refs` |  | `{ "req": "需求文档 §3.2", "dev": "复述稿 第 12 行" }`，屏上小字显示 |
| `verify` |  | 会后用什么证据验证 |
| `status` |  | `open`（默认）/ `closed`。closed 的不出暂停点，只在"本轮变化"里提 |

单屏可读性：`req` / `dev` / `risk` / `fix` 各 ≤ 60 字，超了校验器给 warning。

## challenges[]

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✓ | `G1`… |
| `attachTo` |  | 挂到哪个条目；挂上的在该条目之后紧接一屏，结论归到该条目 |
| `question` | ✓ | 挑战问题本身 |
| `why` |  | 为什么要问 |

不挂条目的挑战题单独出一屏、单独一个暂停点。

## delta

```jsonc
{
  "from": "v0.1",
  "closed":  [{ "id": "A02", "reason": "研发稿已改回与需求一致" }],
  "added":   [],
  "changed": [{ "id": "G2", "note": "换题：改问首页过滤到底改变什么" }],
  "unchanged": "其余 19 项内容未变"
}
```

## 暂停点怎么算

`open` 的 item 各 1 个 + 不挂条目的 challenge 各 1 个 + 挂了条目的 challenge 各 1 个（紧跟其后）。校验器会打印总数。
