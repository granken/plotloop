# 旁白写法

旁白就是会上所有人听到的"主持人原话"。写完给用户过目再配音。

## lines.tsv 格式

```
id<TAB>kind<TAB>section<TAB>minutes<TAB>text
```

| kind | 何时用 | 是否暂停 |
|---|---|---|
| `open` | 开场与规则（片头） | 否 |
| `phrase` | 结论口令说明 | 否 |
| `delta` | 本轮变化（增量模式） | 否 |
| `section` | 节标题 | 否 |
| `item` | 分歧条目 | ✓ |
| `grill` | 挑战题 | ✓ |
| `close` | 会后闭环说明 | 否 |

## 规则

1. **编号读口语**：写"A零七""A十八""G二"，TTS 才读得自然；字幕由构建脚本换回 `A07`。
2. **一条一个结构**：编号 + 标题 → 需求怎么说 → 研发怎么理解 → 风险 → 建议（明说"建议是"）→ "请暂停，确认……"。
3. **结尾必须是"请暂停"+ 本次要定什么**，听完就知道要讨论出什么。
4. **不评判人**：资料没读到说"这是资料可达性的问题，不是谁的问题"。
5. **建议不说成决定**：用"建议""可以考虑"，不用"我们决定""必须"。
6. **长度**：条目 80–130 字；按每秒约 6 个字估时长，每个暂停卡后再留约 4.5 秒。20 项的会，全片约 11–12 分钟。
7. **开场三件事**：这段视频是主持人；分几节、几个暂停点；规则（已定不重议 / 技术事实由研发拿证据 / 结论按口令说）。
8. **口令单独一段**，并说"会后录音转文字，AI 按这个格式回填"。

## 示例

```
intro	open		0	下午好。这段视频是今天对齐会的主持人。我们分两节，过一遍四个分歧点。每到暂停提示，请暂停视频，讨论出结论再继续。规则有三条：已经确认的事项不再重新投票；技术事实由研发拿证据；结论请按固定格式说出来。
A03	item	S2	6	A零三，取消订单。需求写的是，骑手接单前用户可以随时取消，并且马上退款。研发稿写的是，首期暂不做取消按钮。没有按钮，不等于没有取消能力，风险是这条能力被静默砍掉。建议是：不强加按钮，但明确取消入口在哪里、退款多久到账。请暂停，确认首期用户能不能取消、从哪里取消。
```
